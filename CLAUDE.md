# Правила проекта: инструментальный софт

Этот проект — инструментальное ПО (расчётные программы, анализ видео и т.п.). Точность расчётов важнее скорости разработки.

## Команда агентов и порядок работы

Главная сессия — дирижёр: она запускает агентов, передаёт им результаты друг друга и общается с пользователем. Агенты не запускают друг друга сами.

1. **requirements-detective** — ПЕРВЫМ разбирает задание и составляет вопросы. Главная сессия задаёт эти вопросы пользователю (через AskUserQuestion, не больше 4 за раз), затем снова вызывает детектива с ответами — он пишет `docs/requirements.md`.
2. **project-planner** — по `docs/requirements.md` пишет `docs/plan.md`: архитектуру, этапы, задачи и назначенного агента. План показывается пользователю на одобрение до начала разработки.
3. Дальше главная сессия выполняет план, запуская агентов в указанном порядке:
   - **physics-math-reviewer** — ДО написания расчётного кода проверяет формулы, размерности и границы применимости, готовит контрольные примеры.
   - Основной код пишет главная сессия (или general-purpose агент).
   - **code-formula-auditor** — ПОСЛЕ написания или изменения расчётного кода проверяет соответствие кода формулам и пишет тесты на контрольных примерах.
   - **ui-designer** — делает интерфейс; перед началом ВСЕГДА спрашивает стиль (минималистичный / красивый / классический), если он ещё не записан в `docs/design.md`.
   - **feature-scout** — предлагает дополнительные функции; реализует только то, что одобрил пользователь.
4. Если требования меняются по ходу — снова детектив, затем перепланирование у project-planner.

Задачи, помеченные в плане как параллельные, запускаются одновременно, каждая в отдельном git worktree.

## Общие правила

- Все физические величины внутри кода — в СИ; перевод единиц только на входе и выходе.
- У каждой формулы в коде — комментарий с источником (стандарт, учебник, страница).
- Расчётный код отделён от интерфейса (отдельный модуль без зависимостей от UI) и покрыт тестами.
- Ошибки и предупреждения пользователю — на понятном языке, рядом с проблемным полем.
- Документы проекта: `docs/requirements.md`, `docs/plan.md`, `docs/design.md`, `docs/backlog.md`.
