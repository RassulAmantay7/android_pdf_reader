# Техническое задание: личный PDF-ридер для Android

Версия: 1.0 (v1) · Дата: 2026-11-09 · Автор: requirements-detective
Источник: задание пользователя «Я хочу создать свой pdf reader для своего телефона (у меня андроид)» + ответы на уточняющие вопросы.

---

## 1. Цель и границы

**Цель.** Простое личное приложение для чтения PDF на Android: без рекламы, без доступа к интернету, без лишних функций. Помимо чтения — пометки и заполнение PDF-форм.

**Пользователь.** Один человек — автор заказа. Русскоязычный, телефон на Android 15 или новее. Не обязательно разработчик: всё, что ему нужно делать руками (получить APK, установить), должно быть описано пошаговой инструкцией.

**Критерий успеха v1.** Пользователь скачивает APK из GitHub Actions и устанавливает его на телефон. После этого он открывает обычный текстовый PDF из «Загрузок» или мессенджера через «Открыть с помощью», читает его в обоих режимах, ищет текст, ставит закладки, делает пометки и заполняет форму, а затем сохраняет результат копией или поверх оригинала — и всё это без единого сетевого разрешения.

## 2. Функциональные требования

Обозначения приоритета: **M** — обязательно в v1, **S** — желательно в v1 (можно перенести, если мешает срокам/стабильности).

### 2.1. Открытие файлов

| ID | Требование | Приоритет | Как проверить |
|---|---|---|---|
| FR-1 | Приложение регистрируется как обработчик `ACTION_VIEW` для MIME `application/pdf` (схемы `content://` и `file://`) и появляется в системном диалоге «Открыть с помощью». | M | На телефоне нажать PDF в «Файлах»/«Загрузках»/Telegram → в списке есть приложение → файл открывается. |
| FR-2 | Кнопка «Открыть файл» на главном экране вызывает системный выбор файлов (Storage Access Framework, `ACTION_OPEN_DOCUMENT`, фильтр `application/pdf`). Разрешения на всё хранилище (`MANAGE_EXTERNAL_STORAGE`, `READ_EXTERNAL_STORAGE`) НЕ запрашиваются. | M | Открыть файл через кнопку; в манифесте нет перечисленных разрешений. |
| FR-3 | Для файлов, открытых через SAF, приложение берёт постоянное разрешение (`takePersistableUriPermission`), чтобы файл можно было снова открыть из списка недавних после перезапуска. Для файлов из «Открыть с помощью», где постоянное разрешение недоступно, приложение хранит недавний файл как ссылку, а если доступ потерян — показывает понятное сообщение «Файл больше недоступен, откройте его заново» и предлагает убрать из списка. | M | Открыть файл → перезапустить телефон → открыть из недавних. Открыть файл из мессенджера → после перезапуска либо открывается, либо выдаётся описанное сообщение (не падение). |
| FR-4 | Файлы с паролем: при открытии запрашивается пароль (поле ввода, сообщение «Неверный пароль» рядом с полем при ошибке). | S | Открыть тестовый зашифрованный PDF с верным и неверным паролем. |
| FR-5 | Повреждённый или не-PDF файл: приложение не падает, показывает сообщение «Не удалось открыть файл: он повреждён или это не PDF». | M | Открыть переименованный .txt → сообщение, не crash. |

| FR-7 | Обложки генерируются локально и кэшируются во внутреннем хранилище приложения; повторный показ списка не перерисовывает их заново. | M | Повторный вход на главный экран — обложки появляются мгновенно (нет повторной генерации; проверяется по коду/логам). |

### 2.3. Чтение

| ID | Требование | Приоритет | Как проверить |
|---|---|---|---|
| FR-10 | Два режима просмотра с переключателем на панели: (а) **вертикальная непрерывная прокрутка**; (б) **постраничное листание как в книге** — горизонтальный свайп, одна страница на экран. Выбранный режим запоминается глобально (последний выбранный). | M | Переключить режим → поведение меняется; перезапуск → режим сохранён. |
| FR-11 | Масштабирование щипком (pinch-zoom) и двойным касанием (по двойному тапу — переключение между «по ширине» и увеличенным масштабом). Диапазон масштаба — минимум от «страница целиком» до 500 %. При увеличении текст перерисовывается чётко (не растянутый растр). | M | Увеличить до 400 % — текст чёткий; двойной тап возвращает «по ширине». |
| FR-12 | Запоминание позиции: для каждого файла сохраняется последняя страница (и, по возможности, масштаб); при повторном открытии документ открывается на ней. | M | Открыть, долистать до стр. 37, закрыть, открыть снова → стр. 37. |
| FR-13 | Переход на страницу: индикатор «стр. N из M»; по нажатию — ввод номера страницы. Неверный номер (0, больше M, не число) — сообщение рядом с полем «Введите число от 1 до M». | M | Ввод 0 / M+1 / «abc» → сообщение; корректный номер → переход. |
| FR-14 | Ползунок (скраббер) для быстрой перемотки по документу. | S | Перетащить ползунок → номер страницы меняется, страница отображается. |
| FR-15 | Оглавление (outline/bookmarks из самого PDF), если оно есть в файле: список разделов с переходом по нажатию. Если оглавления нет — пункт скрыт или показывает «В документе нет оглавления». | S | Файл с оглавлением → переход по пункту; файл без → сообщение. |
| FR-16 | Внутренние ссылки PDF (переход на страницу) работают по нажатию. Внешние ссылки (URL) — открываются системным браузером только после подтверждения «Открыть ссылку в браузере?» (само приложение в сеть не ходит). | S | Нажать внутреннюю ссылку → переход; внешнюю → диалог. |
| FR-17 | Полноэкранный режим чтения: касание по центру страницы скрывает/показывает панели. | M | Тап по центру → панели скрываются/появляются. |

## 3. Нефункциональные требования

### 3.1. Платформа и сборка

| ID | Требование |
|---|---|
| NFR-1 | Нативное Android-приложение на Kotlin. Устройство пользователя — **Android 15 (API 35) или новее**. Выбор `minSdk` — за планировщиком (не ниже, чем требует выбранная библиотека; не выше 35). `targetSdk` — актуальный на момент сборки. |
| NFR-2 | **Единственное место компиляции — GitHub Actions** (в среде разработки нет Android SDK и Google Maven). Workflow собирает APK при каждом push в основную ветку и по ручному запуску (`workflow_dispatch`), прогоняет модульные тесты и lint, публикует APK как артефакт сборки (и/или как GitHub Release по тегу). |
| NFR-3 | Сборка воспроизводима: зафиксированы версии Gradle (wrapper), AGP, Kotlin, всех зависимостей; без динамических версий (`+`, `latest`). |
| NFR-4 | Подпись APK: личный release-ключ, хранящийся в GitHub Secrets (keystore в base64 + пароли), чтобы обновления ставились поверх старой версии без удаления. Если секреты не заданы — сборка подписывается debug-ключом с явной пометкой в имени файла (`-debug`). В репозитории ключи и пароли не хранятся. Инструкция по созданию ключа — в README. |
| NFR-5 | Поскольку локальной компиляции нет, логика без зависимостей от Android (модели данных, логика списка недавних, отпечаток файла, расчёт масштаба/страниц, валидация ввода номера страницы) выносится в отдельный чистый Kotlin/JVM-модуль, покрытый модульными тестами, которые запускаются в GitHub Actions. |

### 3.2. Приватность и безопасность

| ID | Требование |
|---|---|
| NFR-6 | В итоговом (merged) манифесте **нет разрешения `android.permission.INTERNET`** и других сетевых разрешений; это автоматически проверяется в CI (например, `aapt2 dump permissions` / анализ merged manifest), сборка падает, если разрешение появилось (в т.ч. из транзитивной зависимости). |
| NFR-7 | Нет рекламы, аналитики, трекеров, crash-репортеров с отправкой данных, Google Play Services-зависимостей. |
| NFR-8 | Не запрашиваются широкие разрешения на хранилище (см. FR-2); доступ к файлам — только через SAF и `ACTION_VIEW`. |
| NFR-9 | Данные приложения (недавние, закладки, обложки, черновики) — только во внутреннем хранилище приложения. Резервное копирование Android (auto backup) — отключено или ограничено, чтобы содержимое документов не уходило в облако. |

## 4. Что НЕ входит в v1

- Распознавание текста в сканах (OCR) и поиск по сканам.
- Перекомпоновка текста под ширину экрана (reflow).
- Цифровая подпись сертификатом; формы XFA.
- Редактирование самого содержимого PDF (текста, изображений), объединение/разделение/поворот страниц, создание PDF.
- Облачная синхронизация, любые сетевые функции, обмен пометками.
- Публикация в Google Play / F-Droid, другие пользователи и устройства.
- Чтение других форматов (EPUB, DJVU, CBZ, DOCX).
- Режим двух страниц рядом (разворот), чтение вслух (TTS).
- Поддержка Android ниже 15 (может появиться как побочный эффект выбора `minSdk`, но не проверяется).
- Сборка APK в среде разработки (только GitHub Actions).

Дополнительные идеи — на рассмотрение feature-scout, в `docs/backlog.md`.

## 5. Допущения

1. На устройстве пользователя **Android 15 (API 35) или новее**. Значит, встроенные `PdfRenderer` API текста/поиска/выделения/форм (`searchText`, `selectContent`, `getFormWidgetInfos`, `applyEdit`, `write`) доступны без бэкпортов.
2. У пользователя есть (или будет создан) аккаунт GitHub и репозиторий; GitHub Actions доступен (бесплатные минуты для публичного репозитория или квоты для приватного достаточно).
3. Типичные документы — обычные текстовые PDF; сканы открываются и читаются, но поиск/выделение по ним не работает (FR-21).
4. Телефон сертифицирован Google (обычный Android-смартфон), поэтому требования о проверке разработчика (NFR-11) к нему применимы с 2027 г. или раньше в зависимости от страны.
5. Пользователь не разработчик: все ручные шаги (секреты GitHub, установка APK) снабжаются пошаговыми инструкциями.
6. «Обложка» — миниатюра первой страницы PDF.
7. Хранение закладок/позиции — внутри приложения, а пометки/формы — внутри PDF (стандартные аннотации/поля).

## 6. Риски и открытые вопросы для планировщика

| # | Риск | Последствие | Рекомендация |
|---|---|---|---|
| R-1 | Нет локальной компиляции: ошибки сборки видны только в GitHub Actions; на телефоне проверяет только пользователь. | Долгий цикл «правка → сборка → проверка», риск неработающего APK. | Маленькие шаги, CI на каждый push, максимум логики — в тестируемом JVM-модуле (NFR-5); ранний «скелетный» APK для проверки установки. |
| R-2 | Рекомендуемая основа — **androidx.pdf** (`PdfViewerFragment` / `EditablePdfViewerFragment`, поиск, выделение, маркер/перо/ластик/undo, заполнение форм). Она в статусе **1.0.0-beta01** (26.08.2026), часть API (`EditablePdfViewerFragment`, `AnnotationsView`) помечена `@ExperimentalPdfApi`. | API может меняться; возможны баги. | Зафиксировать версию; изолировать работу с библиотекой за собственным интерфейсом. Альтернатива — собственный просмотрщик поверх встроенного `PdfRenderer` (API 35) — больше кода, но стабильный API. Решение — за планировщиком. |
| R-3 | Неизвестно, поддерживает ли androidx.pdf **постраничное горизонтальное листание** (FR-10б) и **текстовые заметки** (FR-28) — по документации явно заявлены вертикальная прокрутка, маркер, перо, ластик. | Может потребоваться свой режим листания поверх `PdfRenderer` и своя реализация заметок. | Первая задача плана — прототип/спайк, проверяющий FR-10б, FR-28, FR-29, FR-32 на выбранной основе. |
| R-4 | Запись в PDF (пометки, формы) может испортить файл. | Потеря документа пользователя. | FR-36–FR-38: спрашивать каждый раз, писать через временный файл, проверять результат. |
| R-5 | Транзитивные зависимости могут добавить разрешение INTERNET в merged manifest. | Нарушение NFR-6. | Проверка в CI; при необходимости `tools:node="remove"` в манифесте. |
| R-6 | Правила проверки разработчика Android (NFR-11) меняются. | Инструкция по установке устареет. | Перепроверить перед выпуском. |
| R-7 | Доступ к файлам из «Открыть с помощью» временный (FR-3). | Часть недавних файлов нельзя открыть после перезапуска. | Понятное сообщение; при желании — опция «сохранять копию во внутреннее хранилище» (в backlog). |
